# Onyx skin (fork-only)

A "glow in glass" look for this fork: true-black canvas, recovery in discrete green / yellow / red bands,
an ambient glow in today's band colour behind each screen, glass cards over blue and violet light, glowing
score rings, Barlow Condensed numerals, and WHOOP's score names (Recovery / Strain / Sleep). Dark mode
only; Light mode is upstream's.

Never proposed upstream. WHOOP's design language only: no logos, wordmark, assets or proprietary fonts.

## Where it lives

All logic is in `app/src/main/java/com/noop/onyx/OnyxSkin.kt`. Upstream files carry only one-line calls,
each tagged `// FORK:` — after an upstream merge, `git grep -n "FORK: Onyx"` lists every one:

| Upstream file | Hook | Effect |
|---|---|---|
| `ui/Theme.kt` `NoopTheme` | `OnyxSkin.tokensFor(dark)` | the whole dark palette |
| `ui/Theme.kt` `recoveryStops` | `OnyxSkin.recoveryStopsOrNull()` | banded recovery rings |
| `ui/Theme.kt` `NoopType.display` / `number` | `OnyxSkin.numeralFamily` | condensed numerals |
| `ui/Components.kt` `frostedCardSurface` | `OnyxSkin.drawGlassCard` | glass cards |
| `ui/Components.kt` `GlowRing` | `OnyxSkin.drawArcGlow` | ring halo |
| `ui/Components.kt` `glowRingCenterTextStyle` | `OnyxSkin.numeralFamily` | ring numerals |
| `ui/LiquidScreenSky.kt` backdrop slot | `OnyxSkin.Backdrop()` | ambient glow |
| `ui/TodayScreen.kt` `HeroScoreVessel`, Charge hero | `forcesRings`, `PublishHeroTint` | rings + glow colour |

Score names are a build-type resource overlay, `app/src/release/res/values/strings.xml`, generated by
`onyx/gen_score_names.py`. **Re-run it after every upstream merge.** A few names are hard-coded in Kotlin
on deeper screens (Insights, Compare, the sleep-performance header) and stay NOOP's.

Fonts: `app/src/main/res/font/onyx_barlow_condensed_*.ttf`, SIL OFL 1.1 (`app/src/main/java/com/noop/onyx/BARLOW-OFL.txt`).

## Building and installing

`./gradlew assembleFullRelease -PstagingRelease` (JDK 17) produces `com.noop.whoop.staging`, signed with
the repo's `fork-debug.keystore`, the same key upstream's staging builds use. So it installs over an
upstream staging build in place, keeping all data, and an upstream staging build can later be installed
back over it, provided its version code is not lower.

## Onyx Focus (layout)

`app/src/main/java/com/noop/onyx/OnyxFocus.kt`, its own switch (`OnyxFocus.ENABLED`), independent of the
colours and applied in Light mode too. Hooks are tagged `// FORK: Onyx Focus` / `// FORK: Onyx names`:

- **Today** (`TodayScreen.kt`): only Hero, a one-line read (in place of Synthesis), and five key metrics
  (HRV, resting HR, respiratory, blood oxygen, skin temp). Cardio footnote and provenance footer off.
- **Bar** (`AppRoot.kt`): Today · Sleep · Strain (Workouts) · Trends · More. Coach gets a More row.
- **Trends** (`TrendsScreen.kt`): Week in review, Recovery, HRV, resting HR, Sleep. Training load,
  calendar and export off the tab.
- **Strain** (`WorkoutsScreen.kt`): opens on 7 days.
- **Sleep** (`SleepScreen.kt`): no morning "Open Journal" sheet.
- **Names in code** (`WeeklyDigestCard.kt`, Workouts, Sleep): `OnyxFocus.scoreNames(...)`, call sites only.

Nothing is deleted and no preference is rewritten: switch it off and the wearer's saved layout returns.
